# セキュリティレビューです。

## 対象ファイル

- `backend/api/handlers/MessageHandler.php`
- `backend/api/handlers/DirectMessageHandler.php`
- `backend/api/handlers/ThreadHandler.php`
- `backend/api/handlers/GroupHandler.php`
- `backend/api/handlers/FriendHandler.php`
- `backend/FileRateLimiter.php` 既存の処理を確認して、必要なら修正を。（今のところ問題なし）

## 修正内容

### １ メッセージ、DM、フレンド関連

- メッセージ送信やDM、フレンド申請などに回数制限を追加する。
- 短時間に大量のリクエストが送られた場合は、429を返して拒否する。
- メッセージの文字数にも上限を設定する。
- メッセージ取得時に、そのスレッドを閲覧する権限があるか必ず確認する。
- ブロックしている相手へのDMやフレンド申請を拒否する。
- 制限や権限チェックはフロントエンドだけでなく、必ずPHP側でも行う。

### ２ フロントエンドの修正

対象となるディレクトリ：
- `frontend/index.php`
- `frontend/js/index.js`

- `onclick` などのHTMLに直接書かれたイベント処理を削除する。
- ボタンには `data-action` や `id` を設定する。
- `index.js` の `setupEventListeners()` にイベント処理をまとめる。
- `addEventListener()` を使ってボタンのクリックなどを管理する。
- 送信ボタンの連打を防ぐため、送信中はボタンを無効化する。
- タイムアウト処理も追加し、送信が正常に完了しない場合に対応する。

### ３ CSPの強化（多分一番大事）

対象となるディレクトリ：
- `backend/SecurityUtil.php`

- `SecurityUtil::sendSecurityHeaders()` でセキュリティ設定を管理する。
- `script-src` から `'unsafe-inline'` を削除することを目指す。
- HTML内に直接書かれたJavaScriptを外部JSファイルに移す。
- 一度にすべて変更せず、送信・削除・作成などの重要な操作から順番に対応する。
- 変更後は画面や各機能が正常に動作するか確認する。

### ４ ファイルのアップロード・ダウンロード

対象となるディレクトリ：
- `backend/api/BaseHandler.php`
- `frontend/download.php`

- アップロードできるファイルのサイズを最大10MBに制限する。
- ファイルの形式や種類もサーバー側で確認する。
- ダウンロード時に、そのファイルを閲覧する権限があるか確認する。
- グループの添付ファイルは、そのグループの参加者だけがダウンロードできるようにする。
- 権限がない場合は403を返す。

### ５ その他の修正

対象となるディレクトリ：
- `backend/api/handlers/LocationHandler.php`
- `frontend/signup_process.php`
- `frontend/index.php`
- `backend/api/Handler.php`

- 位置情報の更新処理にCSRF対策を追加する。トークンがない場合や不正な場合は拒否する。
- アカウント登録時に、入力形式や文字数、長さをチェックする。
- 本番環境ではPHPのエラー詳細を画面に表示しない。
- APIで発生した例外の詳細はサーバーログに記録し、ユーザーには一般的なエラーメッセージだけを返す。

## 作業上の注意

- 既存の構造や処理をなるべく維持する。
- 不必要なクラスやファイルを新しく追加しない。
- 既存のセキュリティ対策と重複しないよう、最初にコードを確認する。
- 一度に大量の変更を加えず、機能ごとに修正と動作確認を行う。
- 修正後はGitHubにPushする前に差分を確認し、不要な変更やデバッグコードが残っていないか確認する。
- 既存機能に影響が出ていないことを確認してからPushする。
